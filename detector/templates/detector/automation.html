Automated detection

A GNN trained on 20% of a card file's labels scores every transaction, and the reinforcement-learning agent decides every transaction on its own: it blocks and opens cases, escalates to analysts, holds back, or approves, and learns from fraud labels as they arrive.

A run takes about 5 minutes on two CPU cores; planting adversarial examples adds one to two.

From the command line: python manage.py inject_rings credit_card_clean.csv credit_card_rings.csv, then python manage.py automate_detection --target credit_card_rings.csv. Adversarial test: python manage.py automate_detection --target credit_card_clean.csv --adversarial [--adversarial-training].

What happens

  1. The GNN is trained on the file's revealed labels (20%), on the first 60% of the file in time; every transaction is then scored using only earlier transactions.
  2. The agent learns on the validation period, two hours at a time, with labels arriving six hours late: it sets the alert threshold, how much to trust evidence from linked accounts, cards and devices, and whether to pseudo-label.
  3. Automation. The best agent runs the test period alone and keeps learning. Every transaction is blocked into a case, escalated, held back (with the reason) or approved.
  4. Cases and rings. Escalations that share a card, device, IP address, account (24 h) or merchant (72 h, across accounts) are grouped; a case across two or more accounts is a ring.
  5. Adversarial examples (optional). Frauds built to evade the GNN, including a white-box attack that edits them until the GNN stops flagging them. The run page shows how many of each kind the GNN and the agent still caught, and with adversarial training whether the attacker can adapt.
  6. Planted rings (optional). Six rings of known members are added to the file. The run page then shows, ring by ring, how many of the test-period ring transactions the agent escalated and grouped into ring cases.
